# AI-ассистент с поддержкой RAG и потоковых ответов (SSE)

Асинхронный сервис искусственного интеллекта на FastAPI с поддержкой диалогов, загрузки пользовательских документов и контекстного поиска по ним (RAG — Retrieval-Augmented Generation). Проект демонстрирует интеграцию с современными LLM, потоковую передачу ответов через Server-Sent Events (SSE), семантическую обработку файлов и чистую модульную архитектуру.

## Ключевые возможности

- **Потоковые ответы в реальном времени (SSE)** — генерация ответов LLM транслируется по токенам через протокол Server-Sent Events без задержек.
- **Интеллектуальная обработка документов** — поддержка форматов `.txt`, `.md`, `.csv`, `.pdf` с очисткой текста и разбиением на смысловые фрагменты (чанки) с настраиваемым перекрытием.
- **Семантический поиск (RAG)** — расчёт векторных представлений (эмбеддингов), поиск top-K наиболее релевантных фрагментов по косинусному сходству и передача контекста в системный промпт модели.
- **Управление контекстом диалога** — сохранение истории переписки, поддержка системных инструкций и автоматическая генерация заголовков тем.
- **Безопасность и отказоустойчивость** — JWT-аутентификация с безопасным хешированием паролей и защита API от перегрузок (Rate Limiting).

## Эндпоинты API

### Аутентификация
| Метод | Путь | Описание |
|---|---|---|
| POST | `/api/auth/register` | Регистрация нового пользователя |
| POST | `/api/auth/login` | Вход в систему (возвращает JWT access token) |
| GET | `/api/auth/me` | Данные текущего пользователя (требует заголовок Bearer) |

### Чат с ассистентом
| Метод | Путь | Описание |
|---|---|---|
| POST | `/api/chat` | Отправка сообщения и получение полного ответа от модели |
| POST | `/api/chat/stream` | Потоковый ответ модели в реальном времени (SSE) |

Формат тела запроса:
```json
{
  "message": "Каковы основные условия договора из загруженного документа?",
  "conversation_id": "uuid-диалога",
  "use_documents": true
}
```

### Диалоги
| Метод | Путь | Описание |
|---|---|---|
| GET | `/api/conversations` | Список диалогов текущего пользователя (пагинация) |
| GET | `/api/conversations/{id}` | Детальная история сообщений в диалоге |
| PUT | `/api/conversations/{id}` | Изменение заголовка или системного промпта |
| DELETE | `/api/conversations/{id}` | Удаление диалога со всеми сообщениями |

### Документы и база знаний
| Метод | Путь | Описание |
|---|---|---|
| POST | `/api/documents/upload` | Загрузка файла (TXT, MD, CSV, PDF) и индексация чанков |
| GET | `/api/documents` | Список всех загруженных документов пользователя |
| GET | `/api/documents/{id}` | Детали документа со статистикой фрагментов |
| DELETE | `/api/documents/{id}` | Удаление документа и его векторных эмбеддингов |

## Как устроен механизм RAG

1. Пользователь загружает документ. Сервис извлекает чистый текст и делит его на блоки с заданным шагом и перекрытием (`chunk_size`, `chunk_overlap`).
2. Для каждого фрагмента вычисляется вектор признаков через OpenAI Embeddings API и сохраняется в базе данных.
3. При отправке сообщения с флагом `use_documents: true`:
   - Векторизуется текст входящего вопроса пользователя.
   - По косинусному расстоянию отбираются наиболее близкие по смыслу чанки из базы знаний.
   - Найденные фрагменты подставляются в системный контекст модели.
   - LLM формирует точный ответ строго на основе предоставленных материалов.

## Установка и запуск

### Локальный запуск

1. Создайте и активируйте виртуальное окружение:
```bash
python -m venv venv
venv\Scripts\activate     # Windows
source venv/bin/activate  # Linux/macOS
```

2. Установите зависимости:
```bash
pip install -r requirements.txt
```

3. Настройте конфигурацию:
```bash
copy .env.example .env
```
Заполните параметры в `.env` (ключ `OPENAI_API_KEY`, параметры подключения к базе данных).

4. Запустите базу данных PostgreSQL и Redis (например, через Docker):
```bash
docker-compose up -d db redis
```

5. Запустите приложение:
```bash
uvicorn app.main:app --reload
```

Сервер будет доступен по адресу `http://localhost:8000`.  
Интерактивная документация API Swagger: `http://localhost:8000/docs`

### Запуск через Docker Compose

Запуск всего приложения в изолированном окружении:

```bash
docker-compose up -d --build
```

## Демонстрационный режим (без API-ключа OpenAI)

Если переменная `OPENAI_API_KEY` не задана:
- Приложение автоматически активирует демонстрационный режим.
- Ответы чата симулируются информативными заглушками.
- Векторные эмбеддинги генерируются детерминированно для тестирования пайплайна RAG без расхода средств.

## Тестирование

Запуск автоматических тестов:

```bash
pytest tests/ -v
```

Все тесты полностью автономны, используют SQLite в памяти и моки для внешних вызовов API OpenAI.

## Переменные окружения

| Переменная | Описание | Значение по умолчанию |
|---|---|---|
| `DATABASE_URL` | Подключение к PostgreSQL (asyncpg) | `postgresql+asyncpg://postgres:postgres@localhost:5432/ai_assistant` |
| `REDIS_URL` | Подключение к Redis | `redis://localhost:6379/0` |
| `SECRET_KEY` | Секретный ключ подписи JWT | `secret` |
| `OPENAI_API_KEY` | Ключ доступа к OpenAI API | `""` |
| `OPENAI_BASE_URL` | Базовый URL API OpenAI или совместимого шлюза | `https://api.openai.com/v1` |
| `LLM_MODEL` | Используемая модель для генерации текста | `gpt-3.5-turbo` |
| `EMBEDDING_MODEL` | Модель для построения эмбеддингов | `text-embedding-ada-002` |
| `MAX_TOKENS` | Максимальное число токенов в ответе | `2000` |
| `CHUNK_SIZE` | Размер фрагмента текста (в символах) | `500` |
| `CHUNK_OVERLAP` | Размер перекрытия фрагментов (в символах) | `50` |
| `TOP_K_RESULTS` | Количество чанков, передаваемых в контекст | `5` |
| `UPLOAD_DIR` | Каталог для временного хранения файлов | `uploads` |

## Стек технологий

- **FastAPI**, **Uvicorn** — асинхронный фреймворк и веб-сервер
- **SQLAlchemy 2.0 (async)**, **asyncpg** — асинхронная работа с базой данных
- **OpenAI API** — генерация ответов и расчёт эмбеддингов
- **Pydantic v2** — валидация схем и параметров
- **PostgreSQL** — надёжное хранение диалогов и документов
- **Redis** — кэширование и поддержка лимитов
- **Docker**, **Docker Compose** — контейнеризация
- **pytest**, **httpx** — тестирование
